# Known limitations

Gaps that are known and accepted for v0.1.0. Each entry says why and what would fix it.

| Area | Limitation | Why / mitigation |
|---|---|---|
| Evals | Dev/test split is stratified by question, not by document: 52 of the 160 gold documents serve both dev and test questions. | `questions.v1.jsonl` is append-only; the reranker uses document-agnostic features and τ is a single scalar, so the leakage surface is small. A `questions.v2.jsonl` split by document is the fix. |
| Evals | Labels are by construction; no human review yet. | "Maintainer review of 40 questions" is listed in `PROGRESS.md` → Needs the maintainer. |
| Audit | Removing the newest audit rows (tail truncation by a superuser) is not detectable from the chain alone. | Row and statement triggers block UPDATE/DELETE/TRUNCATE for the app; anchoring the latest hash externally (logs or a WORM store) would close it. |
| Providers | Titan and OpenAI embedding fixtures are synthetic, following the documented response shapes. | No provider keys in the build environment; `make record-fixtures` re-records them. |
| Dependencies | `langchain-community` is being sunset upstream; its loaders are kept because FR-2 names them. | Migrate to standalone loader packages when they cover PDF/DOCX/HTML. |
| Packaging | The corpus generator ships as a top-level `data` package in the wheel. | Only the API image installs it (for `crag seed`); rename to `compliance_rag_data` before publishing a wheel. |
| Harness | The pre-tool guard cannot see dataset writes made from inside a program (for example `python -c "open(...,'a')"`). | `tests/unit/data/test_questions.py` fails if the committed datasets drift from the generator. |
| Harness | Claude Code deny rules win over allow rules, so `Read(.env.example)` is blocked by `Read(.env.*)`. | Kept for safety; `.env.example` is readable with shell tools and documented in README. |
| Retrieval | With cold caches, both legs can exceed the 250 ms leg budget and the ask returns 503 `retrieval_unavailable` (`retryable: true`). Observed on the dev stack after a restart: first pgvector query ≈ 2.1 s and first BM25 query ≈ 150–250 ms for a new filter shape. | The API warms up before serving (`pg_prewarm` of the chunk heap and indexes, one retrieval per role; ≈ 2.8 s, 13,647 blocks on the seeded stack, from the `warm_up` log line). Page-cache eviction under memory pressure can still make a first query slow; clients retry on `retryable`. |
| Tests | Schemathesis runs every operation as `content_admin` only; non-admin authorisation is covered by targeted tests (`test_every_v1_operation_requires_a_token`, admin 403s, 404 ownership tests), not fuzzed. | A second parametrised run per role would double the contract suite's time. |
| Tests | Several integration tests mutate the session-scoped `api_env` (AML-0107 extra versions, KYC-0042 ACL changed and restored in `finally`), so ordering matters in principle. | Mutations are additive or restored; the demo test uses its own environment. A per-module environment would cost a seed per module. |
| Streaming | If Redis fails mid-run while a client is behind, events between the client's cursor and the last sequence written to Redis exist only in Redis and are skipped; numbering continues in memory and `final` (authoritative) still arrives. | §4.7 accepts no resume while Redis is down; copying the Redis tail into memory on failure is impossible once Redis is unreachable. |
| Web | The evidence viewer shows the cited chunk (with its section and validity), not the whole version text at 72ch; “Current version vN” links to the document timeline. | The API serves chunks (`GET /v1/chunks/{id}`), not assembled version text; a version-text endpoint would be needed. |
| Web | The citation quote travels in the evidence URL (`?quote=`), so it can appear in browser history. | nginx has `access_log off` and `Referrer-Policy: no-referrer`; router state or a claim lookup would avoid it. |
| Web | The jobs screen shows the latest 200 jobs with no “Load more”. | The API caps `limit` at 500; paging can follow the library's cursor pattern. |
| Evals | Ragas faithfulness (live-only metric in §11) is not implemented, and no live eval has been run (no provider key in this build). | `scripts/eval_live.py` runs the RAG suite metrics live within the budget; adding Ragas needs its package and a live judge model — listed under Needs the maintainer. |
| Web | At 375 px the header (title, navigation, persona switcher, user, sign-out, theme) wraps to about 190 px before the content; screenshots exist at 1280 px only, while axe runs at 1280 and 375 px in both themes. | A disclosure menu for the account controls below `md` would shorten it; no content is hidden or clipped (axe and reflow pass). |
| Evals | The injectable FakeLLM only obeys canary instructions in sentences of 12–400 characters and never follows URL instructions, so the output guard's unknown-URL path is covered by unit tests (`tests/unit/guard`), not by the offline red-team. | A live red-team run (`DEMO_MODE=live`, Needs the maintainer) exercises a real model's compliance. |
| Evals | The key-fact grader matches the expected numbers anywhere in the answer (units and the citing document are not checked); in the committed run no case scores 1 without citing a gold document. | Requiring the value in a claim that cites a gold document would be stricter; it would need a new metric version. |
| API | With Redis down, the in-memory fallback for run event streams is per process: with 3 API workers a `GET /v1/runs/{id}/events` usually reaches another worker than the one running the ask and returns 404 until Redis is back (non-streaming asks keep working). | §4.7 allows "no resume" without Redis; a sticky routing or a synchronous fallback for `stream: true` would close it. Set `API_WORKERS=1` to keep streams working without Redis at the cost of throughput. |
| API | Each API worker keeps per-chunk reranker caches (term sets and the stored 384-d vectors of every visible chunk, loaded at start-up: the `warm_up` log line on 2026-10-18 shows `reranker_chunks` 22730 and `seconds` 8.4–8.8 per worker, including the Postgres prewarm); with 3 workers the API container used 1.887 GiB (`docker stats --no-stream` on 2026-10-18 after `make up`, `make demo` and the 300-case eval run). | Lower `API_WORKERS` on small hosts; the caches are bounded (`VECTOR_CACHE_SIZE`, `lru_cache` sizes). |
| Observability | The `observability` profile shows traces only when the app exports them: start it with `OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4318`. Arq job spans are not linked to the API trace that enqueued them. | Propagating the trace context through the job payload would link them. |
| Docker | NFR-7 (`make up` healthy < 5 min) does not hold for the very first `make up` on a machine: MinIO is compiled from source (343 s on 2026-10-18, of which 192 s compiling). Later starts reuse the release-tagged MinIO image even with an empty build cache: the verification run measured 215 s (`evals/reports/time_up.json`, which keeps the latest run only); the console output of earlier fresh-clone runs on 2026-10-18 showed 206, 171, 163, 171, 176 (`f636ecd`), 224 (`fcfdde6`) and 200 s (`bfdae1b`), and a dev-stack start with a warm build cache 42 s. GitHub runners always start without images: the CI workflows build the MinIO image in a step of its own before `make up` (one `make up` that included the compile took 368 s, evals run 39153674631). A change to `docker/minio.Dockerfile` that keeps the release tag needs `docker compose build minio` (CI builds it every time). | MinIO is built from source with patched modules so that the image has no HIGH/CRITICAL findings (`docker/minio.Dockerfile`; "Image hygiene" in `docs/DECISIONS.md`). Publishing the built images (`release.yml` pushes to GHCR on a `v*` tag) and pulling them would remove the compile. |
| Ingestion | `crag jobs replay-failed` re-queues failed ingest jobs only; a failed ACL sync is retried by the `reconcile_acl` cron instead. | ACL syncs are reconciled every minute from Postgres, so they need no manual replay. |
| Evaluation | The offline LSA model, and so every offline eval number, is reproducible on x86-64 hosts with AVX2 only: the fit pins OpenBLAS to its Haswell kernels and one thread, and other architectures use other kernels and fit a slightly different model (OpenBLAS also warns "Core not found" at start on ARM); an x86-64 CPU without AVX2 cannot run the Haswell kernels at all (illegal instruction), so it must unset `OPENBLAS_CORETYPE` and fits a different model too. | Ship the fitted model as a versioned artifact instead of fitting it at seed time. |
| Docker | The worker healthcheck (`scripts/worker_healthcheck.py`) speaks plain Redis over TCP: `rediss://` (TLS) and `unix://` URLs are not supported, and its AUTH path (a URL with a password) is covered by no test; the compose stack uses `redis://redis:6379/0` without a password. | Fall back to `arq --check` for such deployments, or add TLS and a fake-socket test for AUTH. |
| Observability | uvicorn's supervisor process never imports the app, so its own few lines ("Uvicorn running on…", "Started parent process", worker restarts) stay plain text; every worker process logs JSON. | They carry no request data; a JSON `--log-config` for uvicorn would make them uniform. |
| Observability | Logs mask an exception's message (`str(exc)`) wherever it appears in the log text, for the record's `exc_info` exception and, in text holding a traceback, the active one. Exception text that a caller formats differently itself (`repr(exc)` of a multi-line message, `__notes__`, an exception outside both chains) is logged as written. Exception groups are rendered at most 5 levels deep, 10 members wide and 100 members in all; messages of at most 1000 exceptions per record are masked. | Log exceptions with `exc_info` and keep their text out of the message; a lint rule against formatting exceptions into log messages would enforce it. |
| Graph | `superseded` is `valid_to is not None` in answers (`graph/respond.py`) but `valid_to <= today` in the evidence view; BM25 hits carry `valid_to` from the OpenSearch copy, which can trail a closure (the Postgres re-check validates the hit but does not refresh its fields). | No corpus version has a future `valid_to` today, so both agree; refreshing fields from Postgres in the re-check would remove the gap. |
| Graph | `final.answer` is the model's free text, kept only if every number in it is backed by a verified claim and it passes the output guard; with a live model, non-numeric statements in it are not verified. | The UI renders verified claims only; building `answer` from the verified claims would make API clients see only verified text. |
| Auth | A token signed with a newly rotated key that arrives within 10 s of the API's last JWKS fetch gets 401 "unknown signing key" (refetches are throttled so forged key ids cannot force a fetch per request), which signs that user out. | Harmless when the issuer publishes a new key before signing with it; the dev issuer only rotates on restart, which also ends every session. |
| Performance | NFR-2 (time to first verified claim p95 < 300 ms offline, four concurrent clients) sits close to its budget on the 4-vCPU host the stack shares with OpenSearch and Postgres: `evals/reports/bench.json` keeps every run of the configured stack, including runs over budget (up to 395.7 ms), and the `make verify-clean` run of `bfdae1b` failed on it (365.0 ms, console output of a throwaway clone; [DECISIONS.md](DECISIONS.md), 2026-10-18). The tail is CPU contention: in the slowest recorded run (2026-10-18T15:10:25Z) retrieval alone (NFR-1) reached 224.1 ms at p95. | Fixed causes on the way: full GC passes over the reranker caches (`gc.freeze()` after warm-up), two Redis round trips per run event (now one), the bench sharing the host with its own testcontainers, and the worker's `arq --check` healthcheck, which took 3.86 s of CPU every 10 s (now `scripts/worker_healthcheck.py`, about 0.1 s); the three dev-stack runs after that fix measured 225.7, 255.9 and 262.5 ms, and the verification run of `3be0036` 289.4 ms. Remaining options: a host with more cores, or fewer events before the first claim. |
